## 開始時の基準（Phase 48 実測、固定値）

- ブランチ `codex/c49-perf`、base は Phase 48 の `be78b2451`。push・merge・強制 push は禁止。
- 分割構成の正常系は **33テンソル**（IQ3_S / IQ3_XXS）。34本目 `blk.63.attn_output.weight` は既定にしない。
- 熱制限下の性能（同一条件で測ったもの）:

  | 構成 | cap 1785/1497 | cap 2112/1862 |
  |---|---:|---:|
  | CPU 単独 NGL=0 | 828 ms | 684 ms |
  | NGL=9 SPLIT=0 | 1018 ms | 864-890 ms |
  | NGL=9 CPU 比率 0.5 | 988 ms | 853 ms |
  | NGL=9 CPU 比率 0.9 | 1029 ms | 885 ms |

- 1 step = CPU split 717 ms + DSP 実行 95 ms + HTP split の往復 約 163 ms（cap 1785、NGL=9）。
  **163 ms は削減余地の推定値であり、BF16 実装後の削減量を保証しない。必ず実測する。**
- 往復の原因は gated delta net の `blk.NN.ssm_alpha.weight` / `ssm_beta.weight`（bf16、5120x48）が
  HTP の型ゲートを通らず CPU へ落ち、1 layer で 4 回往復すること。33 テンソル分割とは別の損失である。
- DSP のクロックは 2112 MHz 固定。CPU が 3628 -> 2112 -> 1785 MHz に絞られても DSP は変わらない。
  「熱制限で DSP が遅くなる」と書かない。熱制限で遅くなるのは CPU 側のメモリ経路である。

## 優先順位

1. Gate 0: スケジューラ計測の修正（per-scheduler 状態、split 時間の帰属、無効時の従来経路）。
2. Gate 1: BF16 MUL_MAT を HTP で実行する（単独検証まで）。
3. Gate 2: 27B 実モデルで往復を削減し、正味の効果を測る。
4. Gate 3: NGL と CPU 比率の再探索。**熱制限下で CPU 単独より速いこと**が性能の合格条件。
5. Gate 4: IQ3_S / IQ3_XXS の 32x1 カーネル最適化。
6. Gate 5: 32x2、プリフェッチ、IQ2_S などの残り候補。

安全な範囲の実装・診断・検証はユーザー確認なしで進める。確認待ちで停止しない。

## Gate 0：計測の修正

- `ggml_backend_sched_compute_splits()` の計測状態は **スケジューラ単位**で持つ。関数 static を共有しない。
- split 時間を次の4つに分ける: 前 backend の完了待ち (`sync`)、入力コピー (`copy`)、
  backend 呼び出し (`compute`)、合計 (`total`)。`compute` は backend が戻るまでの時間であり、
  非同期投入の復帰時刻を DSP 演算終了時刻として扱わない。
- DSP 側の実行時間は hexagon 側の timeline (`submit` / `wait` / `prep`) で測る。sched 側の
  `compute` と同一視しない。重複して見積もる場合は推定値と明記する。
- 計測無効時 (`GGML_SCHED_SPLIT_TIMING` 未設定) の経路に `ggml_time_us()` もロックも追加しない。
- 可能なら複数スケジューラを同時に走らせる試験を作る。作れない場合は未検証と記録する。

## Gate 1：BF16 MUL_MAT

- 型ゲートを緩めるだけで終わらせない。カーネル、入力配置、出力配置、引数、同期まで通す。
- 対応した型・形状・入力条件だけを「HTP 対応」と宣言する。未対応は安全に CPU へ戻す。
- **対応済み条件で不正な出力を出した後に CPU へ黙って切り替える実装は禁止。**
- 数値契約: BF16 -> FP32 は有限値で厳密（16 bit 左シフト）。積和の結果は CPU 参照とビット一致しない
  ことがあるため、入力変換の厳密性と積和の精度を別々に検証する。
- 検証項目: BF16 の全ビットパターンの変換、0、-0、非正規化数、inf、NaN、実形状 5120x48、
  FP32 入力との混合、正負混合・桁差・打ち消し、出力の有限性、CPU 参照との差分、境界外書き込みの不在。
- 許容誤差は CPU 参照とモデルの数値感度から決め、結果を見て緩めない。最大誤差、相対 L2、RMS を残す。
- HexaTrain (`yuubinnkyoku/HexaTrain`) は HVX 演算と FastRPC の構造だけ参考にする。実行経路が
  違う部分を直接流用しない。流用した場合と設計だけ参考にした場合を区別して記録する。
- HTP 上で `FLOAT32` を宣言しても実行精度を保証しない (HexaTrain の Muon 反復で実測)。
  「FP32 で宣言したから厳密」と書かず、入力変換の厳密性と積和結果の数値正当性を独立に検証する。

## Gate 2/3：往復削減と性能比較

- 変更前後の split 数を `GGML_SCHED_DEBUG=1` で比較する。26 split/token は実測値であって目標値ではない。
- 測るもの: split 数、転送量、同期回数、同期・転送の合計、BF16 積の時間、DSP 全体、1 token の経過時間、
  メモリ増加、CPU と DSP の実行順序。往復削減から BF16 の追加費用を引いた**正味**を出す。
- 比較は同一入力・同一 NGL・同等の周波数と温度で、実行順序を交互にし、複数組の中央値とばらつきを残す。
  段 0 を含む全体と、段 0 を除いた結果を分けて報告する。
- 数値正当性: 2 -> 4 -> 16 ステップ、CPU 参照、フル HTP 参照、logits 差分、有限値、センチネル 0。
  既存 33 テンソルの分割正当性を壊さない。**新しい比率のビット一致を、別比率の結果で代用しない。**
- `CPU_FRAC=1.0` を CPU 単独の代用にしない。CPU 単独は NGL=0 で測る。
- 33 テンソルの行分割実装は削除しない。比較用に残し、`GGML_HEXAGON_SPLIT=1` を既定にしない。
- 34 本目 `blk.63.attn_output.weight` の未解決事項で、優先作業を停止しない。既定は 33 テンソルのまま。

## Gate 4：IQ3 カーネル

- 32x1（1 token 生成の経路）を優先する。32x2 は主に prefill 向けとして扱い、32x1 を犠牲にしない。
- 重み復号、LUT gather、符号展開、スケール計算、HVX 命令数、レジスタ、VTCM、メモリアクセスに分解する。
  生成アセンブリを確認できるときは、ソース上の演算数ではなく実際の命令を見る。
- 変更は小さく分け、単独カーネルと実モデルの両方で測る。単独で速くモデル全体で遅い変更は採用しない。

## 安全条件

- 1 試験 180 秒以内、Swap-out 増分 1024 MiB、DSP 異常、OOM 兆候、強い熱制限で停止する。
  温度保護・ZRAM・重要サービス・安全ガードに介入しない。ADB が TCP のみなら再起動しない。
- 未同期の DSP 出力を読まない。不正な計算結果を正常扱いしない。未検証を pass と書かない。
- 実機が使えないときはホスト側の実装・解析・単体試験へ移る。
