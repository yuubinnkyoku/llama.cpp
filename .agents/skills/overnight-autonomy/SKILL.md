# 夜間自律開発

## 基本原則

- **目的を達成するために自律判断する。** ユーザーが不在であることを前提に、許可済みの範囲で実装・診断・修正・検証を進める。安全な選択肢があるのに「試してよいか」と質問して停止しない。
- **再試行回数に上限は設けない。** ただし同じ条件での無意味な再実行はしない。再試行には新しい仮説・診断情報・変更・環境回復のいずれかが必要。進展しなければ別の作業へ切り替える。
- **危険な実行は即座に止める。** 安全ガードが発動した試験は中断し、原因を記録してから別の安全な条件で再開する。ガードを解除して続けない。
- **質問と停止を混同しない。** 追加の権限や明示的な承認が不可欠なら、その操作は行わず、権限不要の有益な作業を続ける。代替作業も尽きたときだけ BLOCKED にする。
- **明示された禁止事項は厳守。** このSkillは権限を増やさず、破壊的操作・安全装置の解除・禁止された変更を正当化しない。

## 作業手順

1. 最新の引き継ぎ資料・ソース・Git状態・実機状態を確認し、「目標／合格条件／許可範囲／禁止事項／次の試験」を短く固定する。古い計画より新しい実測と明示指示を優先する。
2. **小さく変更 → 検証 → 記録 → コミット**を繰り返す。検証前の成功宣言、未測定値のゼロ表記、比較条件が異なる性能主張は禁止。
3. 失敗したらログ・終了コード・最後に通過した地点を収集し、仮説を立てて一条件ずつ変更する。必要なら成功済みの経路へ戻す。回数ではなく、**新しい情報が得られるか**で続行を判断する。
4. 容量・メモリ・性能・接続で詰まったら、検証済みの回避策を安全性を確認したうえで自律適用する。指示された「初期条件」を、明示的な恒久禁止と取り違えない。危険が残る案は使わない。
5. 実機が使えないときは、ホスト側の実装・静的検証・試験整備・資料更新へ移る。接続不能のまま無意味な再接続を繰り返さない。
6. 各段階の合格条件を満たすまで次の危険度・規模へ進まない。対象範囲を勝手に拡大しない。
7. 終了時は **PASS / PARTIAL / FAIL / BLOCKED** を区別し、実測・未検証・変更ファイル・コミット・再開コマンド・次の一手を簡潔に残す。ユーザーが起きるまで確認待ちにしない。
