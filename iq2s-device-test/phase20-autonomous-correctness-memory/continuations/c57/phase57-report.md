## §1 目標1: NGL=44 の既定化 - PASS

### §1.1 変更内容

`p53_run.sh`（端末側 runner、リポジトリにも `continuations/c57/p53_run.sh` として保存）:

1. `NGL=${3:-16}` -> **`NGL=${3:-44}`**
2. NGL>=24 のとき、暖機の全ファイル residency ゲートを自動で無効化する:

```sh
if [ "$NGL" -ge 24 ]; then
    WARM_SKIP_TOUCH=${WARM_SKIP_TOUCH:-1}
    WARM_RES_MIN_PCT=${WARM_RES_MIN_PCT:-0}
    export WARM_SKIP_TOUCH WARM_RES_MIN_PCT
fi
```

理由: HTP にコピーした重みの元ページは `P20_EARLY_SOURCE_RELEASE` で意図的に解放されるため、
**NGL を上げるとファイル全体の resident 率は原理的に上がらない**（Phase 56 §2.2）。
既定値 90 は `warmup-c43.sh` 側で不変のまま、runner が NGL に応じた値を明示的に渡す形にした。
値は `P53_PROBE ... warm_skip 1 warm_min 0` として全 run のログに残る。

### §1.2 回帰（既定 NGL=44、32-step）

## §2 目標2: バッチ固定費の削減 - PARTIAL

### §2.1 まず実測: キャッシュ整備は固定費ではなかった

`GGML_HEXAGON_PROFILE=3`（HTP_PROF_TRACE）で、DSP が記録する `HTP_TRACE_EVT_L2FLUSH`

`qurt_mem_cache_clean(0,0,FLUSH_INVALIDATE_ALL,DCACHE)` + `hex_l2fetch_block`）と
`:1294-1300`（バッチ終了時）、および `htp-tensor.c` の範囲 flush を囲んでいる。

run `20261117-011813-29129`（NGL=44、128 prefill + 4 decode、DSP 1,708.8 MHz）:

| 項目 | 実測 |
| --- | --- |
| L2FLUSH スパン数 | 59,132 |
| 平均 | **9,784 cycles = 5.7 µs** |
| 最大 | **46,262 cycles = 27.1 µs** |
| 最小 | 149 cycles = 0.1 µs |

**キャッシュ整備は 1 回あたり数 µs から 27 µs で、150-230 ms の固定費ではない。**
Phase 56 §4.3 の「候補」は**実測で否定された**。

### §2.2 DSP バッチ時間の内訳

同じ run の per-op プロファイルと OPBATCH を突き合わせると、バッチは 2 種類に分かれる:

| バッチ | OPBATCH usec | op 数 | op 合計 usec | 差（op に帰属しない時間） |
| --- | --- | --- | --- | --- |
| 小 | 96,751 | 25 | 13,834 | **+82,917** |
| 大 | 11,620 | 268 | 95,983 | -84,363（並列実行で合計 > 実時間） |
| 小 | 15,253 | 25 | 11,129 | +4,124 |
| 小 | 99,486 | 56 | 14,987 | **+84,499** |
| 大 | 60,433 | 282 | 98,948 | -38,515 |

op 数が少ないバッチ（25-56 op）は 96-100 ms かかるのに、op のプロファイル合計は 14-15 ms。
差の約 83 ms は **op のプロファイルに帰属しない時間**で、`proc_op_req` がワーカーに
投げた非同期処理を `work_queue_suspend` で待つ時間だと解釈できる（コードを読んだ限り）。
つまり **DSP は実際に働いている**（固定費ではなく実計算）。

### §2.3 OPPOLL の A/B（NGL=44）

を ABBA で 2 組。`run_split53.sh` は OPPOLL を 0 に固定するので、`run53.sh` を直接呼んだ。

| 2 | 1 | 1 | 53.31 | 744 |

OPPOLL=0 は 784 と 3,390 の二峰性、OPPOLL=1 は 744 と 802。
**速い側では両者に差がない**（744-802 対 784）。遅い側（3,390）が OPPOLL=0 で出たが、
n=2 では偶然と区別できない。

### §2.6 判定

NGL=56 が実用域に入ることを実測した。これは次の一手の選択肢を広げる。

1. **NGL=44 が既定になった。** 暖機ゲートは NGL>=24 で自動的に無効化され、その事実がログに残る。
